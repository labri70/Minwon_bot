# screen_spec.md - 삼성생명 민원 지식봇 한 화면 기획

## 1. 무엇을 위해

삼성생명 민원 지식봇은 상담사/기획 담당자가 고객 질문을 입력하면 관련 FAQ를 찾고, 근거가 붙은 참고용 답변 초안을 빠르게 확인하는 한 화면 도구다. 실제 고객 정보나 확정 판단을 다루는 시스템이 아니라, 공개·더미 FAQ 기반의 교육용 데모다.

## 2. 무엇을 접을지

- 실고객 정보, 계약번호, 주민번호, 계좌번호, 전화번호 같은 개인정보 입력은 막는다.
- 보험금, 환급금, 한도, 결제일, 지급 가능 여부는 확정처럼 답하지 않는다.
- 근거 FAQ가 없거나 범위 밖 질문이면 답변 생성보다 담당자 확인을 우선한다.
- 자동 발송, 실제 계약 조회, 실제 약관 판단은 만들지 않는다.

## 3. 정보 구조

화면은 모바일 상담 앱처럼 한 화면에서 위에서 아래로 흐른다.

1. 상단 바
   - 뒤로가기 아이콘
   - 제목: 삼성생명 민원 지식봇
   - 검색/새로고침 아이콘

2. 안내 영역
   - 날짜 또는 데모 배지
   - 봇 인사말: "안녕하세요. 민원 FAQ를 근거로 참고용 답변을 도와드릴게요."
   - 안전 문구: "금액·확정 판단은 담당자 확인이 필요합니다."

3. 대화 영역
   - 사용자 질문 말풍선
   - 로딩 말풍선
   - 답변 카드
   - 근거 FAQ 카드 목록
   - 담당자 확인 필요 배지

4. 하단 입력 영역
   - 질문 입력창
   - 실행 버튼
   - 개인정보 감지 시 입력창 아래 오류 문구

## 4. 핵심 흐름

질문 입력 -> 로딩 -> 답변 + 근거 -> 담당자 확인

1. 사용자가 질문을 입력한다.
2. 개인정보 비슷한 숫자가 있으면 실행을 막고 안내한다.
3. 질문하기를 누르면 로딩 상태를 보여준다.
4. FAQ 검색 결과가 있으면 참고용 답변과 근거 FAQ를 보여준다.
5. 금액·범위 밖·근거 없음이면 "담당자 확인 필요" 상태로 전환한다.

## 5. 화면 상태 5종

| 상태 | 화면 표시 | UX 문구 |
|---|---|---|
| 초기 | 봇 인사말과 빈 입력창 | 궁금한 민원 질문을 입력해주세요. |
| 입력 중 | 입력창 활성화, 실행 버튼 활성/비활성 | 개인정보나 계약번호는 입력하지 마세요. |
| 로딩 | 봇 말풍선에 점 애니메이션 느낌 | 관련 FAQ를 찾고 있어요. |
| 결과 | 답변 카드 + 근거 FAQ 리스트 | 참고용 답변입니다. 실제 처리는 담당자 확인 후 진행하세요. |
| 오류·범위 밖 | 코랄 배지 + 상담사 연결 문구 | 근거가 부족해 담당자 확인이 필요합니다. |

## 6. 컴포넌트

- 질문 입력창: 한 줄 입력, 모바일에서는 하단 고정
- 실행 버튼: 종이비행기 또는 화살표 아이콘
- 사용자 말풍선: 오른쪽 정렬
- 봇 말풍선: 왼쪽 정렬, 작은 원형 봇 아이콘 포함
- 답변 카드: 답변 본문, "근거: FAQ #번호" 표시
- 근거 FAQ 리스트: 카테고리, 질문, 답변, source 표시
- 담당자 확인 필요 배지: 금액·범위 밖·근거 없음일 때 표시
- 면책 배너: 화면 상단 또는 답변 카드 하단에 짧게 표시

## 7. UX 라이팅

- Placeholder: "민원 내용을 입력하세요."
- 기본 인사: "안녕하세요. 공개 FAQ를 기준으로 참고용 답변을 도와드릴게요."
- 입력 없음: "질문을 먼저 입력해주세요."
- 개인정보 감지: "개인정보로 보이는 숫자는 입력할 수 없습니다."
- 로딩: "관련 FAQ를 찾고 있어요."
- 결과 없음: "관련 FAQ를 찾지 못했습니다. 담당자 확인이 필요합니다."
- 담당자 연결: "이 질문은 담당자 확인이 필요합니다."
- 면책: "AI 답변은 참고용 초안이며, 금액·확정 판단은 상담사/약관 확인이 필요합니다."

## 8. 접근성

- 모바일 우선 1열 구조로 만든다.
- 입력창 -> 실행 버튼 -> 답변 -> 근거 FAQ 순서로 키보드 이동이 자연스럽게 한다.
- 버튼에는 명확한 `aria-label`을 둔다.
- 연한 회색 말풍선 위 텍스트 대비를 충분히 확보한다.
- 담당자 확인 상태는 색상만 쓰지 않고 텍스트 배지도 함께 표시한다.

## 9. 디자인 방향

두 번째 참고 이미지처럼 모바일 메신저 느낌을 가져간다. 흰 배경, 둥근 말풍선, 하단 입력창, 작은 봇 아이콘을 사용한다. 삼성생명 서비스처럼 보이도록 블루 계열을 주 색으로 쓰되, 위험/담당자 확인은 코랄 배지로 분리한다. 이후 STEP 6 디자인 단계에서 뉴브루탈리즘 토큰을 적용할 때도 채팅형 정보 구조는 유지한다.

## 10. UI 구현 기준

`index.html` 화면 뼈대는 Tailwind CSS를 사용한다. 우선은 로컬 미리보기와 수업 진행 속도를 위해 CDN 방식의 Tailwind를 사용하고, 배포 단계에서 필요하면 빌드 방식으로 전환한다. 색상, 간격, 둥근 말풍선, 하단 고정 입력창, 모바일 우선 레이아웃은 Tailwind 유틸리티 클래스로 표현한다.

## 11. 합의 후 index.html 범위

합의되면 `index.html`에는 검색·답변 로직 없이 화면 뼈대만 만든다.

- 입력창
- 실행 버튼
- 샘플 질문 말풍선
- 샘플 답변 카드
- 근거 FAQ 카드 2개
- 담당자 확인 필요 배지
- 개인정보 숫자 입력 차단 UI
- 로컬 미리보기 가능한 단일 HTML
